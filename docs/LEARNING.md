## L0 建立直觉：两张脸到底怎么比（2~3 小时）

### 🎯 概念
1. 人脸识别模型干的事，本质是**把一张脸压成 512 个数字（embedding）**。
2. 比较两张脸 = 比较两个向量的**余弦相似度**（越接近 1 越像）。
3. 判定「是不是同一人」= 相似度 **和一个阈值比大小**。
4. 阈值怎么来的？在带标注的成对数据上扫一遍，选准确率最高的那个。

### 📖 材料
- [`REFERENCES.md`](REFERENCES.md) §7 第 1~3 条（对齐、评测循环、归一化）
- insightface 仓库 README 里的示例代码

### 🔧 动手（**这是本项目最有价值的一小时**）
1. 装好 insightface，取 5 组图片：3 组同一人的不同照片，2 组不同人。
2. 打印每张图的 embedding 维度（应该是 512）。
3. 手算一个余弦相似度，和 `numpy.dot` 的结果对一下（**别直接信库，先信自己算过的**）。
4. 画出 5 组图片的相似度矩阵，观察：
   - 同一个人不同照片的相似度是多少？
   - 不同人之间是多少？
   - **如果同一个人的两张照片相似度只有 0.3，而两个不同人却有 0.4，你该怎么办？**（答案：这张图质量差/姿态极端，或者阈值不能这么定）

### ✅ 自测
1. 余弦相似度的取值范围是什么？为什么不是概率？
2. 忘记 L2 归一化会算成什么？后果是什么？
3. 如果所有人都很相似（比如同一个家族），阈值应该调高还是调低？为什么？
4. 为什么不能用「相似度 > 0.9 就是同一个人」这种绝对规则做全部任务？

## L1 人脸识别基础（1~2 天）

### 🎯 概念
1. **对齐（alignment）**：先检测人脸与 5 个关键点，再用相似变换把人脸摆到标准位置（112×112 模板）。**这一步错了，后面全错。**
2. **训练目标**：把 N 个身份当成 N 分类问题训练（softmax），但普通 softmax 不够——所以要 **ArcFace**：在角度上加一个间隔 `m`，逼着同类更紧、异类更远。
3. **两种任务别混**：
   - **1:1 验证**（verification）：两张图是不是同一人 → 门禁、解锁
   - **1:N 识别**（identification）：这张脸是谁 → 找嫌疑人、相册聚类
   指标完全不同（Accuracy/TAR@FAR vs Rank-1）。
4. **评测协议**：LFW 是 6000 对 + 10 折交叉验证；阈值在每折的**训练半**上选，在**测试半**上测。
5. **数据集与泄漏**：LFW/CALFW/CPLFW 共享身份；训练集与测试集身份重叠会让数字虚高。

### 📖 材料
- ArcFace 原论文（*ArcFace: Additive Angular Margin Loss for Deep Face Recognition*, CVPR 2019）——**重点看 loss 的公式和实验协议，不必看懂全部证明**
- [`REFERENCES.md`](REFERENCES.md) §1（工具箱）、§2（基线模型与期望数字）、§7（协议细节）
- insightface `recognition/arcface_torch` 的 README

### 🔧 动手
1. 用 `buffalo_l` 在 LFW 上跑一次零样本评测，对照 [`REFERENCES.md`](REFERENCES.md) 的期望数字（LFW 99.83 / CFP-FP 99.33 / AgeDB-30 98.23）。**这是 #5 的任务。**
2. **手动实现一次 LFW 10 折协议**（可以先用 1 折），和自己写的"全量选阈值"版本对比——你会看到后者数字偏高，理解为什么。
3. 画出同人/异人两个相似度分布直方图，肉眼找**重叠区**：重叠区就是错误来源。

### ✅ 自测
1. 画一遍人脸识别推理流程（图 → ? → ? → 相似度），标出每一步的输出形状。
2. ArcFace 里的 `margin` 和 `scale` 分别控制什么？把 margin 调到 0 会退化成什么？
3. 1:1 和 1:N 的指标能互相换算吗？为什么不能？
4. 为什么阈值必须在训练半上选，不能在测试半上选？
5. 训练集和评测集身份重叠会发生什么？怎么检查有没有重叠？
6. LFW 99.8% 和 99.0% 的差距，在你的数据规模下算显著吗？（提示：看 L4）

## L2 生成模型基础（2~3 天）

### 🎯 概念
1. **GAN 路线**：生成器 vs 判别器对抗；优点快，缺点训练不稳、容易模式崩塌（mode collapse：生成出来的东西越来越像）。
2. **扩散路线**：前向过程逐步加噪 → 反向过程学习逐步去噪。**扩散模型 = 学一个「去噪器」**。
3. **潜空间扩散（Latent Diffusion）**：不在像素上扩散，而在 VAE 压缩后的潜空间扩散——这就是为什么 Stable Diffusion 在消费级显卡上跑得动。
4. **条件注入的四种方式**（**这是本项目最该搞懂的一张表**）：

| 方式 | 例子 | 控制什么 | 强度 |
|---|---|---|---|
| 文本提示（prompt） | SD 的 text encoder | 语义、风格、粗略属性 | 弱～中 |
| 空间条件（ControlNet） | OpenPose / 深度图 | 姿态、构图、边缘 | 强（空间） |
| 特征适配器（IP-Adapter） | 图像特征注入 cross-attention | 「像这张参考图」 | 中～强 |
| 条件嵌入（embedding） | Arc2Face 直接用 ArcFace embedding | **身份** | 强（身份） |

5. **为什么本项目的核心是第四种**：只有把「身份」本身作为条件，生成的才是**同一个人的不同照片**，而不是「另一个人」。

### 📖 材料
- 任意一篇扩散模型入门科普 + 一篇 latent diffusion（Stable Diffusion）论文的**摘要与方法图**
- [`REFERENCES.md`](REFERENCES.md) §5（生成方法一览）
- `diffusers` 官方文档的 Quicktour 与「Conditioning」相关章节

### 🔧 动手
1. 用 `diffusers` 跑通最小示例：**SD1.5 生成 4 张 512×512 人脸**，记录耗时与显存峰值。**这是 #9 的一部分。**
2. 固定 seed 生成两次，确认结果**完全一致**（理解「可复现」的含义）。
3. 同样的 prompt 换 4 个 seed，观察：哪些属性变了（表情/光照/背景），哪些没变（大致性别/年龄）？
4. **试一次故意失败的实验**：把 prompt 写成「一张模糊的侧脸」，看模型是否真的按你说的做——你会对「文本控制的强度」有真实的体感。

### ✅ 自测
1. 用一句话解释扩散模型的训练目标（不需要公式）。
2. 为什么潜空间扩散比像素空间便宜？代价是什么？
3. 上面四种条件注入方式，哪种最适合「保持身份」？为什么？
4. `num_inference_steps` 从 50 降到 4 会发生什么？为什么 LCM/Turbo 类模型可以少步数？
5. `guidance_scale` 调很大会怎样？（提示：多样性 vs 贴合提示）
6. 为什么生成同样 100 张图，两次运行的显存峰值可能不同？

## L3 身份保持生成（2~3 天）

### 🎯 概念
1. **身份条件的来源**：从参考图提取 ArcFace embedding，注入生成过程。
2. **两条技术路线**：
   - **纯 embedding 条件**（如 Arc2Face）：只吃 embedding，不吃文本 → 身份保真高，但属性控制弱
   - **适配器路线**（如 IP-Adapter-FaceID / InstantID）：在通用 T2I 模型上加身份适配器 → 保留文本控制，身份保真略低
3. **核心矛盾：身份保真 vs 类内多样性**。太像参考图 → 5 张图几乎一样，没有信息量；太不像 → 标签错了（长着别人的脸却标着这个人），是**带毒样本**。
4. **已知瓶颈**：身份条件扩散模型普遍**类内变化不足**（IDperturb, CVPR 2026 明确指出；DCFace 的表情熵与姿态变化偏低）。
5. **量化方式**：身份相似度（生成图 vs 参考图中心的余弦）+ 身份内多样性（生成图两两相似度均值）。

### 📖 材料
- Arc2Face / IP-Adapter / DCFace / IDiff-Face 的项目页与论文方法图（**只看方法图和实验表**）
- [`REFERENCES.md`](REFERENCES.md) §5（含 8 GB 显存可行性与许可陷阱）

### 🔧 动手
1. 用选定的生成器，对**1 个身份生成 4 张**，人工判断像不像。
2. 把「参考图换成该身份的另一张照片」，再生成 4 张，比较稳定性。
3. 用 ArcFace 算：生成图 vs 参考图、生成图 vs 生成图的相似度矩阵，**画热力图**。
4. 做一次「身份内多样性」实验：把身份条件强度调低，看相似度下降多少、多样性上升多少——**亲手感受那个 trade-off**。

### ✅ 自测
1. 为什么不能用「无条件生成 + 给生成的图打上某个人的标签」来做数据扩充？
2. 身份相似度 0.6 和 0.4 的生成图，哪张更适合放进训练集？（提示：不是越高越好，参考 CemiFace 的「中等相似度」发现）
3. 如果某个身份生成出来的图都朝同一个方向偏（比如全是正脸），这会给模型带来什么坏处？
4. 为什么筛选阈值不能用「真实图之间相似度」直接照搬？
5. 你用的生成器，它的训练数据是什么？这可能带来什么偏向或泄漏风险？

## L4 实验方法与统计（1~2 天）

### 🎯 概念
1. **对照组**：没有 real-only 基线的「提升」不是结论。
2. **两种预算口径**（**最容易错的地方**）：
   - **等总图片数**：real+synth 总数 = 纯 real 总数 → 问「合成数据能否**替代**真实数据」
   - **等真实图片数**：在 real 之上追加 synth → 问「追加合成数据能否**增益**」
   两者结论可能相反，**最好都报**。
3. **域差距（domain gap）**：合成图与真实图分布不同导致的性能损失；文献里同预算下约 10 个百分点的差距。
4. **公平比较纪律**：除数据组成外所有超参相同；≥3 个随机种子；报均值±标准差；不在测试集调参。
5. **显著性直觉**：LFW 上 0.1% 的差异就是噪声。判断"有没有提升"要先看**seed 之间的波动**有多大。
6. **公平性 ≠ 整体性能**：已有工作报告合成数据**整体有帮助但公平性「未改善甚至变差」**。要分开报。

### 📖 材料
- [`REFERENCES.md`](REFERENCES.md) §6（域差距、混合比例、人群偏向的实测数字）与 §7 第 5~7 条
- FRCSyn Challenge 的协议说明（要求同一系统训练两次做配对比较）

### 🔧 动手
1. **手算一次 TAR@FAR**：给 20 对样本（10 同人 10 异人）的相似度，手动算 FAR=0.1 时能取到多高的 TAR。**再写代码验证。**
2. 用 3 个 seed 跑同一个配置，记录三个指标值，算出标准差——**亲眼看看「同一配置」能差多少**。
3. 造一个假数据实验：让「合成组」多训 3 个 epoch（其他不变），看指标涨了多少——理解为什么控制变量这么重要。

### ✅ 自测
1. 「等总图片数」和「等真实图片数」分别回答什么问题？为什么不能只报一个？
2. 你的实验里，如果 E4 比 E1 高 0.3%，你怎么判断这是真实提升还是噪声？
3. 为什么合成数据实验对「身份总数」和「每身份图片数」特别敏感？
4. 只看 LFW 会有什么风险？应该补什么指标？
5. 公平性和整体性能，为什么必须分开报告？
6. 为什么不能在测试集上选阈值或调超参？

## L5 伦理、法律与许可（半天）

### 🎯 概念
1. **生物特征数据是敏感数据**：GDPR 第 9 条、中国《个人信息保护法》第 28/29 条都要求更严格的合法性基础（明示/单独同意，或科研例外 + 保障措施）。
2. **数据集的许可各不相同**，很多**明确禁止再分发**（CelebA、RFW），有的**已被撤回**（MS1M、VGGFace2）。
3. **「合成 = 隐私安全」不成立**：成员推断攻击已从多个主流合成数据集中检索出与真实样本高度相似的图。
4. **双刃剑**：身份一致的生成器可直接用于伪造（morphing 攻击）。

### 📖 材料
- [`REFERENCES.md`](REFERENCES.md) §8（许可表与法律链接，全部是一手来源）

### 🔧 动手

2. 检查仓库：`git log --stat --all` 里有没有数据文件？

### ✅ 自测

## L6 论文精读（持续，每周 2 篇）

做法与产出见 #4。建议顺序：

**必读（8 篇，按此顺序）**
1. ArcFace（CVPR 2019）——理解识别模型的训练目标
2. SynFace（ICCV 2021）——第一次系统研究合成-真实差距，指出根因是**类内变化不足 + 域差距**
3. DigiFace-1M（WACV 2023）——**激进的数据增强是缩小域差距的最大杠杆**

5. IDiff-Face（ICCV 2023）——身份条件隐扩散
6. Arc2Face（ECCV 2024）——只用 ArcFace embedding 作条件
7. CemiFace（NeurIPS 2024）——**中等相似度样本比高相似度更有训练价值**
8. Huber et al.（WACV 2024）——生成器继承训练数据的人口统计分布

**选读（按兴趣）**：Vec2Face+/VFace（合成数据训练的模型更有偏）、Digi2Real、ID³、IDperturb（类内多样性瓶颈）、VariFace（公平性引导）、FRCSyn/SDFR 竞赛报告。

## 数学补丁（按需查阅，不要求系统学）

| 概念 | 一句话理解 | 什么时候需要 |
|---|---|---|
| 余弦相似度 | 两向量夹角的余弦 = 归一化后的内积 | 每天 |
| L2 归一化 | 把向量长度变成 1，此时内积 = 余弦 | 每天 |
| Softmax / 交叉熵 | 把 logit 变成概率分布并惩罚错误类 | 理解分类训练 |
| 角度间隔（ArcFace） | 在角度空间给正确类加一个 `m` 的余量，迫使类间分离 | L1 |
| ROC / TAR@FAR | 扫阈值得到的一条曲线；TAR@FAR 是曲线上某点的读数 | L1、L4 |
| 标准差 / 误差棒 | 同一配置多次运行的波动范围 | L4 |
| 前向/反向扩散 | 加噪 / 学去噪 | L2（只需直觉） |
| ELBO | 扩散模型的训练目标下界 | 不需要（跳过） |

> 💡 **学习原则**：不要为了"看懂所有公式"卡住。**先能用、再能解释、最后才是能推导。** 本项目只需要前两层。

## 自测答案要点（先自己做，再对照）

<details>
<summary>展开</summary>

**L0**
1. `[-1, 1]`；它是几何相似度不是概率，不能解释为"是同一个人的概率"。
2. 算成内积（受向量长度影响）；后果是"清晰、对比度高的图"天然得分高，阈值失去意义。
3. 调高（类间本身就很像，需要更严格的判定），并且要报告在这种困难子集上的性能。
4. 因为不同数据集、不同图像质量下相似度分布不同；阈值必须在**目标域**上重新标定。

**L1**
1. 图 → 检测+对齐(112×112) → 网络 → 512 维向量 → L2 归一化 → 余弦相似度。
2. `margin` 控制类间分离的强制程度（0 就退化为普通 softmax/余弦 softmax）；`scale` 控制 logit 的陡峭程度（影响训练难度与收敛）。
3. 不能。1:1 只比两两关系，1:N 涉及与全库比较的排序，指标定义不同。
4. 否则阈值"见过"测试数据，指标虚高（信息泄漏）。
5. 虚高（模型可能只是记住了这些人）；用公开身份重叠名单检查，或直接按身份切分。
6. 不一定显著，要看 seed 间波动；小数据集上 0.8% 的差异都可能只是噪声。

**L2**
1. 训练一个网络去预测"这张带噪图加了什么噪声/如何一步去噪"，推理时从纯噪声反复迭代去噪。
2. 因为潜空间维度低得多（如 64×64×4 vs 512×512×3）；代价是 VAE 重建误差、细节损失。
3. 条件嵌入（embedding）方式，因为身份直接被作为条件，而不是通过语言/图像间接描述。
4. 步数太少 → 图像崩坏/糊；LCM/Turbo 类模型经过蒸馏，学会了少步数直接跳到结果。
5. 太大 → 图像过饱和/僵硬，多样性下降，甚至出现伪影。
6. 因为中间缓存、注意力切片、其他进程占用、显存碎片化等；所以必须实测并记录，而不是估算。

**L3**
1. 因为无条件生成的脸**不是这个人**，给它打上该身份标签就是错误标签（带毒样本），会直接损害模型。
2. 都不一定。太高 → 与参考图雷同、无新信息；太低 → 身份漂移、标签错误。**中等相似度（半困难样本）往往最有价值**。
3. 模型会学到"这个身份只有正脸"，在其他姿态上反而更差——这正是"多样性不足"的危害。
4. 生成图与参考图的相似度分布和真实图之间的相似度分布**不是同一个量**；阈值要在生成数据上扫描并人工抽检。
5. 参见过拟合/泄漏风险：生成器训练数据可能含真实身份，输出可能继承其来源与偏向。

**L4**
1. 前者问"能否替代真实数据"，后者问"追加是否带来增益"；两者结论可能相反，所以要都报。
2. 先看 3 个 seed 的标准差；若 0.3% 小于标准差，就不能称之为提升。
3. 因为身份数决定了分类任务的难度与多样性规模，而每身份图片数决定了类内分布；两者不同会直接改变结果。
4. LFW 已饱和（99.8%+），差异被压缩；应补充不易饱和的指标（TinyFace 1:N Rank-1 或自建 1:N 闭集）。
5. 因为整体提升可能掩盖某些人群/场景的下降；已有工作报告公平性"未改善甚至变差"。
6. 那是信息泄漏，会让结果无法复现到真实场景。

**L5**
1. 衍生数据继承原数据集的许可限制；且对齐裁剪后仍是可识别的人脸生物特征数据。
2. 生成器与版本、生成参数、许可证、"由 AI 生成"声明、使用限制、可检测性结论。
3. 因为合成数据既是隐私工具也是伪造工具，项目有责任量化并公开其可检测性，作为对策讨论的依据。
4. 引用成员推断攻击的实测结果（多个合成数据集可被检索出与真实样本高度相似的图），说明"合成 ≠ 隐私安全"需要泄漏审计才能声称。

</details>

## 常见误区（新手最容易踩的 10 个）

1. **把余弦相似度当概率**——"0.8 就是 80% 是同一个人"是错的。
2. **忘记 L2 归一化**——所有相似度都不可信。
3. **在测试集上选阈值/调参**——数字虚高，无法复现。
4. **训练集与评测集身份重叠**——同上，而且更难发现。
5. **只看 LFW**——它已经饱和，掩盖真实差异。
6. **不做对照组就宣称提升**——可能是"图变多了"而不是"合成数据有用"。
7. **单 seed 下结论**——小数据集上噪声极大。
8. **只看平均指标**——掩盖分桶/分人群的下降。
9. **认为"合成 = 隐私安全"**——已被成员推断攻击证伪。
10. **追求看懂全部数学再动手**——先用起来，理解会在实践中长出来。
