## 1. 目标定义：6 周后你要能拿出什么

### 1.1 四件交付物（缺一不可）

| # | 交付物 | 判断标准 |
|---|---|---|
| 1 | **可复现的仓库** | 别人按 README 能跑出和你一样的数字；两台机器都能跑 |
| 2 | **技术报告**（6~10 页） | 含：问题、方法、实验设置、结果表、结论、**局限**、复现指南 |
| 3 | **展示网站**（静态，5 个页面） | 打开就能看懂：方法图 + 真/合成对比图库 + 指标图表 + 结论 |
| 4 | **一次主动汇报**（≥2 次） | 每次带"能演示的东西 + 一张进展表"，而不是口头描述 |

### 1.2 你的「三个可交付问题」（**这是全项目的重心**）

原来的 5 个研究问题在 60 人时里答不完，砍成 3 个：

| ID | 问题 | 靠什么实验回答 | 亮点 |
|---|---|---|---|
| **Q-A** | **现成的合成人脸数据**加进训练集，识别性能会变好吗？加多少合适？ | E4b（B 轨）+ 比例扫描 3 点 | 直接回答"合成数据有没有用" |
| **Q-B** | **给同一个人生成更多照片（身份保持生成）**，比传统增强更有效吗？ | E4a（A 轨）vs E2（传统增强，**图片总数对齐**） | ⭐ **这是你区别于"调包跑 demo"的核心**：它把"数量"和"多样性"分开了 |
| **Q-C** | 代价是什么？ | 质量/姿态分桶表现 + 许可与可检测性的**文献讨论** | 体现你有工程伦理意识（学长会看这个） |

### 1.3 ⚠️ 一条必须讲清楚的方法学细节（**这条会让你显得很专业**）

B 轨和 A 轨回答的是**两个不同的问题**，绝不能混在一条曲线里：

| 轨道 | 加进去的是什么 | 学名叫法 | 回答 |
|---|---|---|---|
| **B 轨**（下载的 DigiFace-1M / Digi2Real 等） | **新的、合成出来的"人"** | 增加**类别数**（new identities） | 合成身份能否补充**类别多样性**？ |
| **A 轨**（本地对真实身份生成） | **已有那批人的更多照片** | 增加**类内样本数**（more samples per identity） | 同身份的更多变化能否提升**类内泛化**？ |

**报告里必须分两节写**，并各自定义清楚"比例"是什么：
- B 轨比例 = 合成**身份数** / 总身份数（类别层面）
- A 轨比例 = 合成**图片数** / 总图片数（样本层面，身份数不变）

> 把这两个混在一起是这类项目最常见的错误。你只要在报告里明确区分，就已经超过大多数同水平的工作了。

**汇报点 2（W4 末）——主题："有结论了，能演示了"**
- 一张图：**同一身份的真实图 vs 生成图**（这是最抓眼球的）

**汇报时主动说清楚的三件事**（会让你显得很专业）：
1. 我们**分开**测了"增加合成身份"和"给同一身份增加照片"——它们是两个问题；
2. 我们**对齐了图片总数**才敢说"多样性比数量更有效"；
3. 我们记录了**所有没成功的尝试**，并写进了局限。

## 6. 学习方案（针对"零 DL 经验 + 数学好 + Python 少"）

### 6.1 原则：**不单独安排学习周，全部嵌进任务**

每周只花 **30~60 分钟**做"定向阅读"，其余靠动手。`LEARNING.md` 的六阶段按下面的方式压缩：

| 阶段 | 你的做法 | 时间 |
|---|---|---|
| **L0** 直觉 | 必做（W1，手算余弦 + 相似度矩阵） | 1h（两人各 0.5h 已排入） |
| **L1** 识别基础 | **必做**，并且因为数学好，可以深入看 ArcFace 的角度间隔公式 | 1h（W2） |
| **L2** 生成基础 | **压缩为"用中学"**：只读"四种条件注入方式"那张表 + 跑通 4 张生成图 | W4 实操中顺带 |
| **L3** 身份保持 | **压缩**：只抓"保真 vs 多样性"的取舍，其余在实操中理解 | 1h（W4） |
| **L4** 实验方法 | **必做**：手算 TAR@FAR + 用标准差判断显著性（数学优势在这里发挥） | 1h（W5） |
| **L5** 伦理许可 | 半天压缩成 30 分钟：只做"数据许可核对表" | W5 顺带 |
| **L6** 论文 | **只读 5 篇**（不是 15 篇）：ArcFace、SynFace、DigiFace-1M、Arc2Face、Huber et al. | 每周 20 分钟，共 ~1.5h |

### 6.2 你的 Python 短板：前两周刻意练「三件套」

你算法强但 Python 少，**不要试图通读 Python 教程**。只练这三样，它们覆盖了本项目 90% 的代码：

1. **`argparse`**：每个脚本都有 `--config / --dry-run` 入口（照抄你自己写的第一个脚本即可）
2. **`pathlib`**：所有路径用 `Path` 拼接，**禁止手写字符串路径**（这是两人两机不打架的前提）
3. **`pytest`**：每个核心函数配一个"用假数据验证真逻辑"的测试（例如用 3 个已知向量验证余弦相似度）

> 这三样练熟，你的 Python 就够用了；剩下的时间应该花在实验设计和结果解释上——**那才是你的优势区**。

### 6.3 队友的学习路径（差异化）

队友同样零基础，但**不需要碰训练与生成**，所以：

- 优先学 **L1 的评测协议** 与 **L4 的统计**（逻辑清晰、数学味足、不依赖 GPU）；
- 用"网站"作为正反馈来源：每做完一个图表就能看到页面变化；
- 不需要深入扩散模型（L2/L3 只求"能听懂你讲"）。

## 8. 汇报时可能被问到的 8 个问题（提前想好答案）

1. **"你们的数据量这么小，结论可信吗？"** → 承认规模限制；强调我们比的是**内部相对差异**、且关键对比做了 3 seed；绝对值不与论文比。
2. **"为什么不直接在 MS1M 上训练？"** → 消费级显存与时间不允许；我们的贡献是**低成本配方**（RQ5）与方法学对照。
3. **"合成数据到底有没有用？"** → 分两轨回答：增加合成**身份** vs 增加同身份**照片**，这是两个问题，结论可能不同。
4. **"你怎么知道提升不是来自图片变多？"** → 因为我们做了 E2 传统增强对照，**并严格对齐了图片总数**。
5. **"生成的脸和真人像不像？"** → 有量化（身份相似度分布）+ 人工抽检通过率 + 图库展示，包括**不够像的样本**。
6. **"合成数据有隐私问题吗？"** → 有：文献证明合成数据集可能被成员推断攻击检索出真实样本；我们记录了来源与生成参数，并做了可检测性讨论。
7. **"这东西能落地吗？"** → 谈成本收益：A 轨的成本（显存/时间）vs 收益；明确说本项目的规模**不能**外推到工业场景。
8. **"如果重做一次，你会改什么？"** → 提前准备 2 条（例如"先做 B 轨再碰 A 轨""评测器必须早于训练管线"）——这题答好非常加分。
