## 背景 / 为什么做这个

实验跑完不等于项目做完。**没有结论的实验数据只是噪声。**

这个任务要把 `results/summary.csv` 里的一堆数字，翻译成对 `docs/FRAMEWORK.md` §2 那五个研究问题的明确回答，并且**诚实地说清楚这些结论在什么范围内成立**。

对零基础的项目来说，「知道自己不知道什么」比「假装知道」重要得多——这一节写好了，项目就是合格的；写不好，前面所有工作都会显得可疑。

## 目标

一份能让外行读懂、让内行挑不出毛病的结论文档。

## 任务清单

- [ ] 写 `docs/RESULTS.md`，结构固定如下：
  - [ ] **摘要**：5 句话以内说清「做了什么、发现了什么、代价是什么」
  - [ ] **实验设置**：数据规模、训练配置、评测协议、硬件（一段话 + 一张表）
  - [ ] **主要结果表**：每个实验（E0~E6）一行，列出各 benchmark 的均值±标准差
  - [ ] **核心图**：合成比例 vs 性能曲线（来自 {{#14-mix-ratio-matrix}}）
  - [ ] **逐个回答 RQ1~RQ5**：每个 RQ 一节，格式为 `结论 → 证据（数字/图）→ 置信度（高/中/低）→ 可能的原因`
  - [ ] **与文献的对照**：我们的数字/趋势和已发表工作一致吗？不一致的地方怎么解释？（引用 {{#04-background-survey}} 的 `docs/BACKGROUND.md`）
  - [ ] **局限（Limitations）**：至少 5 条，见下
  - [ ] **下一步工作**：如果继续做，最该补的三件事
- [ ] **局限一节必须包含**（照抄没用，要写你自己的情况）：
  - [ ] 数据规模极小（几十个身份），结论不能外推到工业规模
  - [ ] 身份来源单一（LFW 的名人照片），人群/场景覆盖极窄
  - [ ] 生成器自身的偏向会传导到数据集（生成器的人口统计分布继承自其训练数据）
  - [ ] 评测集规模有限，小差异可能在噪声范围内
  - [ ] 单机单卡 8 GB，无法验证更大模型/更高分辨率下的行为
  - [ ] 筛选阈值是人为选择的，不同阈值可能改变结论
- [ ] **措辞审查**：通读一遍，把所有没有数据支撑的断言删掉或降级
  - [ ] 禁止：「显著提升」（除非做过显著性检验）、「证明」、「state-of-the-art」、「完全隐私安全」
  - [ ] 推荐：「在本实验规模下观察到」「差异在 X 个标准差内」「与…趋势一致」
- [ ] 写 `reports/claim_checklist.md`：把每个结论与支撑它的文件路径一一对应（可追溯性检查表）
- [ ] 更新 `README.md` 的结果摘要段（3~5 句话 + 一张图）

## 参考

- 写作结构可参考任何一篇合成人脸数据论文的实验章节，例如 [DCFace (CVPR 2023)](https://arxiv.org/abs/2304.07060)、[IDiff-Face (ICCV 2023)](https://arxiv.org/abs/2308.04995)
- **可直接引用的对照结论**（用来解释你的结果）：
  - 合成数据与真实数据之间存在可测量的 **"Real Gap"**：[VariFace, arXiv:2412.06235](https://arxiv.org/abs/2412.06235)
  - 合成数据训练的模型在**孪生人脸验证**上几乎都失败，且**比真实数据训练的模型更有偏**：[Vec2Face+/VFace, arXiv:2507.17192](https://arxiv.org/abs/2507.17192)
  - 生成器会**继承其训练数据的人口统计分布**：[Huber et al., WACV 2024, arXiv:2311.03970](https://arxiv.org/abs/2311.03970)
  - **在合成图上做偏见审计会得出误导性结论**（同一指标在真实图上结论反转）：[arXiv:2608.23593](https://arxiv.org/abs/2608.23593)
  - 合成数据集可能**泄漏真实训练样本**（成员推断攻击）：[arXiv:2410.24015](https://arxiv.org/abs/2410.24015)

## 附：已核实要点（框架预置，2026-09）——**写结论时可以直接对照的公开数字**

**合成数据能到什么水平（5 基准平均：LFW/CFP-FP/CPLFW/AgeDB/CALFW）**

| 训练数据 | 平均准确率 |
|---|---|
| SynFace（2021） | 74.75 |
| DigiFace-1M（2023） | 83.45 |
| IDiff-Face（2023） | 88.20 |
| DCFace（2023） | 89.56 |
| Arc2Face（2024） | 91.73 |
| HSFace-300K（2025） | 93.52 |
| **纯真实数据 CASIA-WebFace（天花板参照）** | **94.79** |

**两条必须写进「与文献对照」一节的结论**：
1. **差距在缩小但没消失**，且**主要集中在姿态困难的基准（CFP-FP / CPLFW）上**——如果你的实验也呈现「整体提升但姿态桶没提升」，这与文献一致，值得明确指出。
2. **性能提升 ≠ 公平性改善**：已有工作报告「合成数据无论单独用还是混合用都有帮助，但**公平性分数未改善甚至变差**」（[arXiv:2409.02867](https://arxiv.org/abs/2409.02867)）。**这两件事必须分开报**，不要用整体指标掩盖分组差异。

**其他可引用的风险证据**（用于「局限」一节）：
- 身份条件扩散模型普遍**类内变化不足**（IDperturb, CVPR 2026）
- 多个合成数据集被证实**无法通过成员推断攻击的隐私检验**（[arXiv:2410.24015](https://arxiv.org/abs/2410.24015)）
- 生成器**继承其训练数据的人口统计分布**（[arXiv:2311.03970](https://arxiv.org/abs/2311.03970)）

详细版见 [`docs/REFERENCES.md`](../REFERENCES.md) 第 5、6 节。

## 新手提示 / 卡住了怎么办

- **负结果也是结果**。「在本规模下加入合成数据没有带来稳定增益」是一个有价值、可发表的结论，前提是你把实验做严谨了。不要为了好看去挑 seed。
- 写作顺序建议：先写「实验设置」（最客观，好写）→ 再填「主要结果表」（照抄 CSV）→ 再回答 RQ（这部分最难，每个 RQ 写 200 字左右）→ 最后写摘要（最需要提炼，放最后）。
- 措辞审查这一步**不要跳**：新手最容易写「显著提升」，而实际上两组差异可能小于 seed 之间的波动。用标准差来约束你的措辞。
