## 背景 / 为什么做这个

{{#10-identity-preserving-generation}} 解决的是「生成同一个人」，但生成出来的还是**容易样本**——正脸、光照良好、和参考图相似度很高。而人脸识别模型真正栽跟头的地方是：

- **大姿态**（侧脸、俯仰）——监控场景的常态
- **低质量**（运动模糊、强逆光、低分辨率）——真实世界的主流
- **跨年龄**——证件照与现场照的时间跨度
- **人群差异**——不同人群上的性能落差（这正是文献里被反复指出的问题）

这一步做的是**定向补短板**：可控地生成困难样本，看它能不能比「随机生成一堆容易样本」更有效地提升模型。

> 这是加分项（P2）。**只有在前面的 P0/P1 全部完成、且时间富余时才做。**

## 目标

至少在一个维度（姿态 / 质量 / 年龄）上实现可控生成，并用实验说明「定向补充困难样本」是否有效。

## 任务清单

- [ ] 选 **一个**可控维度作为主线（建议按难度递增选：模糊/噪声 → 姿态 → 年龄 → 人群）
- [ ] 实现控制手段（择一）：
  - [ ] 后处理模拟：对生成图施加可控的降质（高斯模糊、下采样、JPEG、运动模糊、亮度/对比度）——最简单，先做这个
  - [ ] 生成时条件控制：用 ControlNet（如 OpenPose / 深度）控制姿态
  - [ ] prompt 属性词控制（注意：SD1.5 级别的模型对属性词响应较弱，不要期望太高）
- [ ] 在 manifest 的 `meta` 中记录属性标签（如 `pose_yaw`、`blur_sigma`、`quality_level`），这是后续分桶评测的依据
- [ ] 生成 3 档 × 每档 ≥20 张，人工确认档位之间**确实有可见差异**
- [ ] 做对照实验（至少一组）：
  - [ ] E4-随机（{{#10-identity-preserving-generation}} 的产出）vs E6-定向（本任务产出），训练规模对齐
  - [ ] 在**分桶评测**上看差异：定向生成是否更能改善「困难桶」的表现？（用 {{#07-evaluator}} 的分桶能力）
- [ ] 更新 `docs/RESULTS.md`：新增一行 + 明确结论（「定向补充有效/无效」都要写）

## 验收标准（Definition of Done）

- [ ] 至少 1 个属性维度可配置控制，产出 ≥60 张带属性标注的图
- [ ] 属性档位的人工确认记录（哪些图属于哪档，肉眼是否分得开）
- [ ] 与 E4 的对照实验有数字（≥1 seed），且区分「整体指标」与「困难桶指标」
- [ ] 如果结论是负面的（定向生成没用），**照实写**，并给出可能原因（样本太少 / 控制不精确 / 模型容量不足）

## 参考

- 定向生成困难样本的思路可参考 **CemiFace**（刻意生成与身份中心「中等相似度」的样本，反而比高相似度样本更有训练价值）：[arXiv:2409.18876](https://arxiv.org/abs/2409.18876)
- 属性×人群的细粒度失败分析参考 **CounterFace**（20 个属性 × 8 个人口统计因素的反事实图像对）：[arXiv:2407.13922](https://arxiv.org/abs/2407.13922)
- 生成器的人群偏向问题（**重要**：生成器会继承其训练数据的人口统计分布）：Huber et al., WACV 2024 — [arXiv:2311.03970](https://arxiv.org/abs/2311.03970)；GAN 过采样「年轻白人面孔」：[arXiv:2208.13061](https://arxiv.org/abs/2208.13061)
- [Diffusers ControlNet 文档](https://huggingface.co/docs/diffusers/using-diffusers/controlnet)
- [Albumentations](https://github.com/albumentations-team/albumentations)（做后处理式降质最省事）

## 附：已核实要点（框架预置，2026-09）

- **姿态控制是本节最难的部分**：Arc2Face 官方 README 自己把「接姿态 ControlNet」称为 **"the most tricky part"**——它需要额外的 EMOCA + PyTorch3D，**在 Windows 上装起来很痛苦**。所以：
  - ✅ **优先做「后处理降质」这一档**（模糊/噪声/低分辨率/JPEG），零依赖、半小时出结果，而且直接对应「低质量场景」这个真实痛点；
  - ⚠️ 姿态维度建议放到最后，或者干脆用 **IP-Adapter-FaceID + prompt 文本控制**（它保留了文本控制能力，而 Arc2Face 是纯 embedding 条件、刻意不支持文本）。
- **「生成困难样本」的方向是有人做过且有效的**：CemiFace 的核心发现就是「与身份中心**中等相似度**的样本比高相似度样本更有训练价值」，可以作为你选择属性档位的理论依据。
- **属性控制的收益上限受限于生成器本身的类内多样性**：IDperturb（CVPR 2026）指出身份条件扩散模型普遍**类内变化不足**。如果你发现「生成的图都差不多」，这不是你参数没调好，而是这个方向的已知瓶颈——照实写进结论即可。

## 新手提示 / 卡住了怎么办

- **先做「后处理降质」这一档**：它对生成模型零改动，半小时能出结果，而且直接对应「低质量场景」这个真实痛点。
- 属性控制不要用 prompt 硬凑（「a blurry photo of a man」经常生成一张清晰的脸加一点背景虚化），后处理反而更可靠、更可控。
- 人群维度的生成**要非常小心**：以「按人群生成」为目的容易滑向人脸分类/画像这类敏感用途（欧盟 AI Act 明确禁止基于生物特征推断种族等的分类系统）。如果要做，请只做**性能差异的测量**，不做人群推断模型，并在报告中说明这一点。
