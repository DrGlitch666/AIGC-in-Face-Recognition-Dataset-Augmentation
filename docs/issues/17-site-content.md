## 背景 / 为什么做这个

骨架搭好后（{{#16-site-skeleton}}），这一步是**把项目讲清楚**。

判断标准不是「页面好不好看」，而是：**一个没听过这个项目的人，从首页点进去，5 分钟内能不能明白——你在解决什么问题、怎么做的、结果如何、有什么限制。**

## 目标

8 个页面全部装上真实内容与真实数据，形成完整的叙事。

## 页面清单与内容要求

| 页面 | 必须回答的问题 | 核心元素 |
|---|---|---|
| `/` 首页 | 这是干什么的？结论是什么？ | 一句话简介、3 张关键图、结论摘要（来自 {{#15-results-conclusion}}） |
| `/method` 方法 | 怎么做的？ | Pipeline 流程图（重绘 `docs/FRAMEWORK.md` §3.1）、**筛选漏斗图**、生成器说明、参数表 |
| `/gallery` 图库 | 生成的东西长什么样？ | 每个身份一行：参考图 + 生成图；**真实 vs 生成对比**；身份内相似度分布图；点击放大 |
| `/metrics` 指标 | 效果到底如何？ | **合成比例 vs 性能曲线**（带误差带）、各实验柱状图（带误差棒）、完整结果表、原始 JSON 下载链接 |
| `/fairness` 公平性与鲁棒性 | 代价是什么？ | 分桶柱状图（姿态/质量）、不同人群分组对比、最大组间差、**对"公平性"措辞的谨慎说明** |
| `/failures` 失败案例 | 什么时候不管用？ | 生成失败样本墙、识别失败样本墙、失败原因分类统计 |
| `/reproduce` 复现指南 | 我能不能自己跑？ | 环境要求、数据获取步骤、命令清单、硬件与耗时实测表、已知坑 |
| `/ethics` 伦理与合规 | 这样做安全吗？ | `docs/ETHICS.md` 的网站版、数据许可说明、合成图声明、可检测性结论（{{#12-synth-detection-report}}） |

## 任务清单

- [ ] 用 `scripts/export_site_data.py` 把真实数据导出到 `site/public/data/`（替换所有 mock）

- [ ] 方法页：重绘 pipeline 图（SVG 或组件化 React 图，不要用论文截图）；筛选漏斗图；生成器参数表（模型、步数、分辨率、显存峰值）
- [ ] 图库页：
  - [ ] 身份分组网格（参考图 vs 生成图）
  - [ ] **每张生成图标注身份相似度分数**（诚实展示，包括不够像的）
  - [ ] 懒加载 + 分页；点击看大图
  - [ ] 显式声明「本页所有非参考图均由 AI 生成」
- [ ] 指标页：核心曲线（带误差带）+ 分组柱状图 + 可排序结果表 + 「下载原始 JSON」按钮

- [ ] 失败案例页：失败样本 + 原因标签 + 统计（**这一页最能体现项目的诚实度，不要省**）
- [ ] 复现指南页：从零到复现的完整命令序列（照抄能跑通）+ 硬件实测表（来自 {{#14-mix-ratio-matrix}} 的 `compute_budget.md`）
- [ ] 伦理页：数据许可表（哪些能用/不能提交）、合成数据声明、可检测性结论、使用限制声明
- [ ] 移动端适配（至少不塌）；键盘可达性（能 Tab 到主要元素）
- [ ] 全站搜索/导航检查：每个页面都能从任意页面两步内到达
- [ ] **数据一致性检查**：网站上的每个数字都能在 `results/` 里找到出处（写一个 `site/README.md` 的对照表）

## 验收标准（Definition of Done）

- [ ] 8 个页面全部有真实内容，**零 mock 数据残留**（全局搜索 `mock` 应无结果）
- [ ] 每个数字都能追到 `results/runs/<exp_id>/metrics.json`
- [ ] 图库页在移动端/窄屏可用；图片总量与加载时间已测量
- [ ] 首页 5 句话结论与 `docs/RESULTS.md` **完全一致**（口径统一）
- [ ] 失败案例页有内容（哪怕只有 10 张），且标注了失败原因
- [ ] 复现指南页的命令**被别人照着跑通过一次**（找同学试，或你自己重装环境验证）
- [ ] 页面上的合成图都有明显标注

## 参考

- 图表呈现方式可参考各个合成人脸数据集项目的项目页（例如 [DCFace](https://github.com/mk-minchul/dcface)、[DigiFace-1M](https://github.com/microsoft/DigiFace1M)、[Arc2Face](https://github.com/foivospar/Arc2Face) 的项目主页），看它们怎么用一张图讲清楚方法
- [ECharts 图表示例库](https://echarts.apache.org/examples/zh/index.html)（直接抄配置，别从零写）
- 可视化诚实性原则：误差棒必须画，坐标轴不从非零点截断（除非明确标注），样本量要写出来

## 新手提示 / 卡住了怎么办

- **不要造假图**：如果某个实验没跑，那一栏就写「未完成」，不要用估计值填充。网站的可信度比完整度重要。
- 先做「首页 + 指标页 + 图库页」这三页（它们承载 80% 的信息），其余页面可以后补。
- 图片处理流水线（缩略图、webp、尺寸控制）建议写成一个脚本，一次跑完，不要手动处理。
- **降级方案**：时间不够时砍掉 `/failures` 与 `/fairness` 的图表部分，但**保留页面并诚实写明「本项未完成」**。
